日志回收说明
================

1. 日志文件位置
--------------
logs/trace.jsonl

如果找不到：
  在终端当前目录下查找（你执行 python main.py 时所在的目录）。
  ls logs/   确认文件存在。


2. 确认日志在写
--------------
测试开始 10 秒后，在另一个终端窗口执行：

  wc -l logs/trace.jsonl

如果行数 > 0 且在增长 → 正常。
如果行数 = 0 → 停止测试，联系李程俊。


3. 测试结束后的操作
--------------
(1) 按 'q' 退出系统（确认终端已返回命令行）
    ⚠️ 如果终端仍在滚动输出，禁止删除日志
(2) 再执行 cp 复制日志文件：
    cp logs/trace.jsonl ~/test_results/测试人姓名_日期_轮次.jsonl

    示例：
    cp logs/trace.jsonl ~/test_results/张三_0501_round1.jsonl

(3) 确认复制成功：
    ls -l ~/test_results/张三_0501_round1.jsonl
    检查文件大小 > 1KB

(4) 再执行 rm 删除原日志（为下一轮清空）：
    rm logs/trace.jsonl


4. 文件命名规范
--------------
格式：测试人姓名_日期_轮次.jsonl

例如：
  张三_0501_round1.jsonl
  张三_0501_round2.jsonl
  张三_0501_stress.jsonl（压力测试）


5. 异常情况处理
--------------
情况A：日志文件不存在
  → 确认是否在项目根目录启动的 python main.py
  → 确认 logs/ 目录是否有写入权限

情况B：日志文件存在但内容为空
  → 确认系统是否正常运行超过 10 秒
  → 确认终端是否有 trace 输出

情况C：日志文件 < 1KB
  → 测试时间太短，重新做一轮至少 3 分钟
  → 确认是否问了至少 3 个问题

情况D：忘记清空日志就开始了下一轮
  → 给文件改个名（加上日期和轮次），不要混在一起
  → 然后用 rm logs/trace.jsonl 清空，重新开始
